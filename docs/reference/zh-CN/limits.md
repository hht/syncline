# 限制

[English](../limits.md) | 简体中文

设计表之前，请先读[表结构](#表结构)和[写入](#写入)。每项限制都写明了超出后会发生什么。少见的情况见[边界情况](edge-cases.md)。

## 表结构

### 列类型

- 列可以存整数、实数和文本。
- 不支持 BLOB、bigint 和 numeric 列。
- 列的存储类型以后不能再改。
- 给已有的表新增非空列，需要一个常量默认值。
- 这些规则对仅本地表同样适用。

不支持的类型会在应用打开数据库时抛错。改了存储类型，或新增非空列却没有常量默认值，会让打开失败：`sync()` 被拒绝，`downloadError` 被设置。对私有空间，`waitForReady()` 也会被拒绝。在云端，违反其中任何一条都会让 `SynclineSpace` 和 `SynclineSharedSpace` 抛错。

### 表名和列名

- 只能使用 ASCII 字母、数字和下划线。
- 不能以数字开头。
- 表名最多 64 个字符。
- 表名不区分大小写：`Note` 和 `note` 是同一张表。请保持表第一次创建时的写法。
- 表名不能以 `_syncline_` 开头，列名不能叫 `_extra`，这两个名字由 Syncline 保留。
- 还有少数名字会被拒绝：见[每个 JavaScript 对象都有的名字](edge-cases.md#不能使用每个-javascript-对象都有的名字)。

违反规则时，应用打开数据库时会抛错；但表名写法与已存储的表不同时，会和改了存储类型一样让打开失败。云端的 `SynclineSpace` 和 `SynclineSharedSpace` 会抛错。

### 主键和外键

- 每张表都需要主键，仅本地表也一样。
- 同步表的每一行都要有其他设备不会产生的主键，例如 UUID。只有在仅本地表里，SQLite 才会补上缺失的整数主键，`autoIncrement` 也只能用在仅本地表上。
- 外键只能指向同一空间内某张同步表的主键。
- 外键列的存储类型必须与它指向的列相同，仅本地表也一样。
- 一行同步数据的主键，按 JSON（UTF-8）编码后最多 512 字节。

向同步表插入时漏掉某个主键列，插入会失败，除非该列有默认值。同步表使用 `autoIncrement` 时，应用打开数据库时会抛错。云端的 `SynclineSpace` 和 `SynclineSharedSpace` 会抛错。

外键指向其他列时，打开私有空间会失败：`waitForReady()` 和 `sync()` 被拒绝，`downloadError` 被设置。云端的 `SynclineSpace` 和 `SynclineSharedSpace` 会抛错。

外键列的存储类型不同时，应用打开数据库时会抛错。云端的 `SynclineSpace` 和 `SynclineSharedSpace` 会抛错。

主键过长时，写入失败并抛出 `ValidationError`。

### 索引和默认值

- 不支持唯一索引、部分索引和表达式索引。
- 默认值必须是常量。

违反规则时，应用打开数据库会抛错。

### 值

- 一行中同步列的总大小最多 1,900,000 字节。只有本地写入检查这一项；服务端写入超过 Cloudflare 的 2 MB 行上限时会失败。
- 文本必须是合法的 UTF-16，单独的代理字符会被拒绝。
- 数字必须是有限值。NaN 会被拒绝，无效的 `Date` 会变成 NaN，同样被拒绝。查询参数传入 NaN 也会抛错。
- 整数列的值必须在 ±9,007,199,254,740,991 之内，这是 JavaScript 数字能精确表示的范围。

本地写入违反规则时会抛错并整体回滚。服务端写入违反文本或数字规则时抛出 `ValidationError`；但以 SQL 表达式给出或由 `$defaultFn` 填充的文本和 NaN 不会被检查，[SQLite 存不下的整数](edge-cases.md#sqlite-存不下的整数可能让服务端写入抛出引擎自己的错误)可能抛出引擎自己的错误。

## 写入

### 大小

- 一次本地写入最多 8 MiB（UTF-8）。
- 一次写入最多修改 100,000 行，级联删除的行也计入。
- 一次写入的主键按 JSON 编码后总计最多 16 MB。

本地写入超限时抛错并整体回滚。服务端写入超限时也抛错并整体回滚，即使代码捕获了错误继续执行。

级联删除过大时，请先分批删除子行。

### 服务端写入

- 每次服务端写入建议控制在几千行以内。
- 超过 CPU 时间限制的写入会重置对象。
- 共享空间只接受服务端写入，每次最多 10,000 行。

参考：在共享空间中向一个桶插入 10,000 行约用 2 秒 CPU，把这些行逐一移到另一个桶约用 5 秒。

### 上传配额

两个可选限制，保护私有空间不受失控上传的影响：

- `writeQuota`：每秒补充 `rate` 行，最多累积 `burst` 行。
- `dailyWrites`：限制每个 UTC 日上传产生的计费行写入。索引和变更记录都计入，服务端写入不计入。

超出任一限制时，云端以 1013 关闭连接。设备稍后重试，同时设置 `uploadError`。

### 连接数

一个私有空间最多同时接受 32 个连接（`connections`）。新连接会关闭最早的连接，被关闭的设备随机等待最多 30 秒再重连。超出上限的设备持续在线时会轮流连接。

### 被暂扣的写入

云端无法执行的上传写入会被暂扣，比如违反了上面某条规则的写入。应用通过 `onHeld` 得到通知。在云端用 `resubmit` 重新提交或丢弃它。

## 下载

### 首次下载

- 首次下载需要约为最终数据库 1.1 倍的空闲磁盘空间。
- 在已有数据上重新下载全部内容，需要约 2 倍。
- 下载中断后会从中断处继续。
- 全量下载完成时，应用在同步表上创建的触发器会被删除；唯一索引、部分索引和表达式索引不会重建。

### 云端部署之后

新增表、新增同步列或修改桶规则后，每台设备会重新下载对应的表。新数据到达之前，设备继续显示旧的行。

部署期间一直连着私有空间的设备，要等该空间下一次有活动（例如有写入，或有别的设备连接）时才会得知。此时云端关闭它的连接（4000），设备下载后重连。

### 数据校验

私有空间每天把设备数据和云端核对一次：新安装时、重置后，以及上一轮完成满一天后，且没有待上传的写入时。每台设备每天最多请求 1,000,000 行（`checksumRowsPerDay`），数据量大的空间一轮要好几天。

不一致的部分会重新下载，待上传的写入保留。

共享空间不做校验。需要重新下载时，调用该空间的 `resync()`。

## 云端存储

- 一个空间最多存 10 GB。超出后写入失败，上传会一直失败（`push.failed`）。
- 云端保留的变更历史，上限取约 64 MiB 和数据量 1/4 中较大的那个。离线时间超过这段历史的设备会重新下载全部内容，待上传的写入保留。

## 共享空间

- 一台设备的订阅按 JSON 编码后最多 8,192 字节（含排序后的桶名），每个桶最多 256 字节。规则只有一个 UUID 参数时，大约是 150 个桶。
- 空间名加上最后一个分片的后缀（默认 16 个分片时是 `#15`），要在 1,024 字节（UTF-8）以内。
- 实时连接默认分散在 16 个广播分片上（`shards`）。每次服务端写入向每个分片各发一次计费请求，并等它们全部应答。
- 按每个分片约 1,000 台同时在线的设备来规划，超过就调大 `shards`。在 Cloudflare 上实测，一次改动要送达同一分片上全部 1,000 台设备时，服务端写入多花约 70 毫秒。
- 每条带过滤条件或桶列的规则，每次插入、每次更新它用到的列，都会多 1 次计费的行写入。
- 一张表最多属于 4,064 条规则。
- 新设备从最近的保存点开始下载，默认每修改 1,000 行记录一个（`chunkRows`）。
- 部署改变了规则覆盖的行之后，云端会以每步最多 20,000 行重新统计这张表。

## 时间

- **实时更新**：消息在 24,000 字节（UTF-8）以内时，改动直接推送到已连接的设备；更大的改动改由设备自行下载。
- **连接卡住**：30 秒内收不到任何数据，设备放弃本次连接并重试。
- **心跳**：空闲 25 秒后发送 ping，30 秒内没收到消息就重连。发送较大的上传期间暂停 ping，暂停时长为按 1 KB/s 传完这些字节所需的时间。
- **重连**：第 n 次重试随机等待，最长 max(spread, min(30 秒, 1 秒 × 2ⁿ))。共享空间按每秒 500 台设备分散重连。
- **导出**：写入 60 秒后导出（`exportDelay`），失败时退避，最长 1 小时；每次闹钟最多导出 10 分钟（`exportBudget`）。
- **时间点恢复**：私有空间可以恢复到最近 30 天内的任意时间点（`restoreSpace`），共享空间不支持。

## 需要知道的事

- **退出登录**：用另一个 `userID` 打开数据库会清除上一个用户的数据。如果那个用户还有待上传的写入，打开会失败并抛出 `PendingWritesError`。
- **应用触发器**：设备每次撤销、重做待上传的写入时，同步表上的触发器都会再次触发。触发器抛错[可能会阻塞下载](edge-cases.md#抛错的触发器可能阻塞下载)。
- **大量待上传写入**：每次私有空间有改动到达、每次打开数据库，设备都会撤销并重做全部待上传的写入，期间读写都要等待。待上传的单行写入达到几千条时，每次要花零点几秒。把多行放进同一个 `write`，重做起来比每行各写一次快。
- **计费行数**：上传的每次写入，除了它修改的行（索引行也算），还要多计 2 次行写入。一个 `write` 改 100 行计 102 行；100 次各改一行的写入计 300 行。
- **自有表的外键**：SQLite 不会强制执行。你的表指向的同步行可能会被删除。
- **更换 token**：用户权限变化时调用 `reconnect()`。共享空间的实时更新会沿用旧权限，最长到旧 token 过期后一分钟；下载每次都会检查 token。
- **Web**：每个站点只能有一个浏览器标签页打开数据库，直到该标签页关闭或刷新。
- **下载进度**是估算值。

## 运行要求

- **Cloudflare**：使用 SQLite 存储的 Durable Objects，兼容日期不早于 2026-04-07。
- **iOS 和 Android**：需要开发构建，不支持 Expo Go。
- **Web**：浏览器需在 Web Worker 中支持 OPFS（`createSyncAccessHandle`）。
- **Expo**：`expo` ~58.0.14。
- **React**：`syncline/react` 需要 `react` ^19.3.0 和 `@tanstack/react-query` ^5.104.0。
- **后台同步**：`syncline/expo/background` 需要 `expo-background-task` ~58.0.11 和 `expo-task-manager` ~58.0.12。
- **Drizzle**：`drizzle-orm` 1.0.0-rc.4。
