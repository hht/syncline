# 限制

[English](../limits.md) | 简体中文

设计表之前，请先读[表结构](#表结构)和[写入](#写入)。每项限制都写明了超出后会发生什么。

## 表结构

### 列类型

- 列可以存整数、实数和文本。
- 不支持 BLOB、bigint 和 numeric 列。
- 列的存储类型以后不能再改。
- 给已有的表新增非空列，需要一个常量默认值。
- 这些规则对仅本地表同样适用。

违反规则时，应用打开数据库或云端创建 `SynclineSpace` 时会抛错。

### 表名和列名

- 只能使用 ASCII 字母、数字和下划线。
- 不能以数字开头。
- 表名最多 64 个字符。
- 表名不区分大小写：`Note` 和 `note` 是同一张表。请保持表第一次创建时的写法。
- 表名不能以 `_syncline_` 开头，列名不能叫 `_extra`，这两个名字由 Syncline 保留。

违反规则时，应用打开数据库或云端创建 `SynclineSpace` 时会抛错。

### 主键和外键

- 每张表都需要主键，仅本地表也一样。
- 外键只能指向同一空间内某张同步表的主键。
- 一行同步数据的主键，按 JSON（UTF-8）编码后最多 512 字节。

外键指向其他列时，打开会失败：`downloadError` 被设置，`sync()` 被拒绝。云端的 `SynclineSpace` 会抛错。

主键过长时，写入失败并抛出 `ValidationError`。

### 索引和默认值

- 不支持唯一索引、部分索引和表达式索引。
- 默认值必须是常量。

违反规则时，应用打开数据库会抛错。

### 值

- 一行中同步列的总大小最多 1,900,000 字节。只有本地写入检查这一项；服务端写入超过 Cloudflare 的 2 MB 行上限时会失败。
- 文本必须是合法的 UTF-16，单独的代理字符会被拒绝。
- 数字必须是有限值。NaN 会被拒绝，无效的 `Date` 会变成 NaN，同样被拒绝。查询参数传入 NaN 也会抛错。
- `-0` 会存成 `0`。

本地写入违反规则时会抛错并整体回滚。服务端写入违反文本或数字规则时抛出 `ValidationError`，但以 SQL 表达式给出或由 `$defaultFn` 填充的值不检查。

## 写入

### 大小

- 一次本地写入最多 8 MiB（UTF-8）。
- 一次写入最多修改 100,000 行，级联删除的行也计入。
- 一次写入的主键按 JSON 编码后总计最多 16 MB。

本地写入超限时抛错并整体回滚。服务端写入超限时也抛错并整体回滚，即使代码捕获了错误继续执行。

级联删除过大时，请先分批删除子行。

### 服务端写入

- 每次服务端写入最多几千行。
- 超过 CPU 时间限制的写入会重置对象。
- 共享空间只接受服务端写入，每次最多 10,000 行。

参考：在共享空间中向一个 bucket 插入 10,000 行约用 2 秒 CPU，把这些行逐一移到另一个 bucket 约用 5 秒。

### 上传配额

两个可选限制，防止私有空间被失控的上传占满：

- `writeQuota`：每秒补充 `rate` 行，最多累积 `burst` 行。
- `dailyWrites`：限制每个 UTC 日上传产生的计费行写入。索引和变更记录都计入，服务端写入不计入。

超出任一限制时，云端以 1013 关闭连接。设备稍后重试，同时设置 `uploadError`。

### 连接数

一个私有空间最多同时接受 32 个连接（`connections`）。新连接会关闭最早的连接。

### 被暂扣的写入

云端无法执行的上传写入会被暂扣，比如违反了上面某条规则的写入。应用通过 `onHeld` 得到通知。在云端用 `resubmit` 重新提交或丢弃它。

## 下载

### 首次下载

- 首次下载需要约为最终数据库 1.1 倍的空闲磁盘空间。
- 在已有数据上重新下载全部内容，需要约 2 倍。
- 下载中断后会从中断处继续。
- 全量下载完成时，应用在同步表上创建的触发器会被删除；唯一索引、部分索引和表达式索引不会重建。

### 云端部署之后

新增表、新增同步列或修改 bucket 规则后，每台设备会重新下载对应的表。新数据到达之前，设备继续显示旧的行。

### 数据校验

私有空间每天把设备数据和云端核对一次：新安装时、重置后，以及上一轮完成满一天后，且没有待上传的写入时。每台设备每天最多请求 1,000,000 行（`checksumRowsPerDay`），数据量大的空间一轮要好几天。

不一致的部分会重新下载，待上传的写入保留。

## 云端存储

- 一个空间最多存 10 GB。超出后写入失败，上传会一直失败（`push.failed`）。
- 云端保留的变更历史，上限取约 64 MiB 和数据量 1/4 中较大的那个。离线时间超过这段历史的设备会重新下载全部内容，待上传的写入保留。

## 共享空间

- 一台设备的订阅按 JSON 编码后最多 8,192 字节（含排序后的 bucket 名），每个 bucket 最多 256 字节。规则只有一个 UUID 参数时，大约是 170 个 bucket。
- 空间名加上最后一个分片的后缀（默认 128 个分片时是 `#127`），要在 1,024 字节（UTF-8）以内。
- 每条带过滤条件或 bucket 列的规则，每次插入、每次更新它用到的列，都会多 1 次计费的行写入。
- 一张表最多属于 4,064 条规则。
- 新设备从最近的保存点开始下载，默认每修改 1,000 行记录一个（`chunkRows`）。
- 部署改变了规则覆盖的行之后，云端会以每步最多 20,000 行重新统计这张表。

## 时间

- **实时更新**：消息在 24,000 字节（UTF-8）以内时，变更直接推送到在线设备；更大的变更改由设备自行下载。
- **连接卡住**：30 秒内收不到任何数据，设备放弃本次连接并重试。
- **心跳**：空闲 25 秒后发送 ping，30 秒内没收到消息就重连。上传大批写入期间暂停 ping，暂停时长按 1 KB/s 传完这些字节估算。
- **重连**：第 n 次重试随机等待，最长 max(spread, min(30 秒, 1 秒 × 2ⁿ))。共享空间按每秒 500 台设备分散重连。
- **导出**：写入 60 秒后导出（`exportDelay`），失败时退避，最长 1 小时；每次闹钟最多导出 10 分钟（`exportBudget`）。
- **时间点恢复**：私有空间可以恢复到最近 30 天内的任意时间点（`restoreSpace`），共享空间不支持。

## 需要知道的事

- **切换用户**：用另一个 `userID` 打开数据库会清除上一个用户的数据。如果那个用户还有待上传的写入，打开会失败并抛出 `PendingWrites`。
- **应用触发器**：设备每次撤销、重做待上传的写入时，同步表上的触发器都会再次触发。触发器抛错可能会阻塞下载，直到删除它。
- **自有表的外键**：SQLite 不会强制执行。你的表指向的同步行可能会被删除。
- **更换 token**：用户权限变化时调用 `reconnect()`。共享空间的实时更新会沿用旧权限，最长到旧 token 过期后一分钟；下载每次都会检查 token。
- **Web**：每个站点只能有一个浏览器标签页打开数据库，直到该标签页关闭或刷新。
- **下载进度**是估算值。
- **云端的大表**：给非常大的表建索引可能超过 CPU 时间限制。遇到时，在 wrangler 中调高 `limits.cpu_ms`。
- **定时任务**：反复导致对象重置的任务，连续 3 次后会暂停一天，并上报失败。
- **本地状态损坏**：Syncline 自己的表（`_syncline_*`）只能由 Syncline 修改。其中保存的待上传写入读不回来时，设备无法同步，也无法打开数据库。删除本地数据库即可恢复，但待上传的写入会丢失。
- **待上传计数**：读取待上传写入数失败时，`status().pending` 保持上一次的值，直到读取成功，因此 `sync()` 可能提前完成。写入仍会上传。

## 连接错误

云端会用以下这些代码关闭连接。设备会自行处理；代码显示在 `uploadError` 或 `downloadError` 中。

| 代码 | 含义 | 设备怎么做 |
|---|---|---|
| 4000 | 设备需要先下载 | 下载后重连 |
| 4001 | token 过期 | 获取新 token 后重连 |
| 4002 | 应用和云端版本不一致 | 云端更新时停止（`updateNeeded`），否则重试 |
| 4003 | 应用和云端表结构不一致 | 检查兼容性，然后连接、停止（`updateNeeded`）或重试 |
| 1007 | 云端拒绝了一批上传的写入（无法解析，或超出限制） | 停止上传，直到应用重启或调用 `resync()` |
| 1008 | 连接过多 | 重试 |
| 1011 | 云端保存上传失败 | 重试 |
| 1013 | 达到上传配额 | 稍后重试 |
| 1003 | 收到二进制消息，或向共享空间上传 | 重试 |

## 运行要求

- **Cloudflare**：使用 SQLite 存储的 Durable Objects，兼容日期不早于 2026-04-07。
- **iOS 和 Android**：需要开发构建，不支持 Expo Go。
- **Web**：浏览器需在 Web Worker 中支持 OPFS（`createSyncAccessHandle`）。
- **Drizzle**：`drizzle-orm` 1.0.0-rc.4。

## 边界情况

很少遇到的情况，大多数应用碰不到。

### 表进出同步

- 表离开私有空间但没有退役时，保留原有的行，直到它重新同步或登录用户切换。
- 只有当某个空间上次打开时声明过这张表，退役才会删除它。
- 共享空间不再声明的表，在该空间打开时被清空。从共享空间转为仅本地的表也一样。
- 从 `localOnly` 移除、且从未同步过的表保持不动。应用不再打开的共享空间的表也一样。
- 表重新加入同步、换到另一个空间，或空间首次声明它时表里已有数据，都会在任何读取之前被清空并重新下载。待上传的写入保留。
- 把一张同步表改名成另一张已声明的表名，不会被发现。空间会把它的行当成另一张表的行。

### 设备

- 切换用户时，被清除的行会在磁盘上清零。更早删除的行可能留在文件的空闲空间里，直到被覆盖。
- 应用在约 48,000 次启动中都有写入却从未同步，就再也无法下载。
- 下载过程中，如果应用更新改了这些表的列或索引，下载会重新开始。
- 本地列类型存不下的值会被放到一边，并给出警告。带这种值到达的行，查询时看不到。
- 设备同步过一个新增了列的版本后，再把云端和应用都回滚，这些设备会不断重试但无法同步。云端重新声明这一列，或应用把它写进 `retired` 后恢复。待上传的写入保留。
- 上传大批写入期间 ping 会暂停，这时连接悄悄断开不会被发现，直到暂停结束：一次 8 MiB 的写入最长约 2.3 小时。

### 共享空间

- 订阅新增 bucket 时，只下载新增的 bucket。删除 bucket 会重新下载全部内容，新数据到达之前旧的行仍然可见。
- 不调用 `reconnect()` 时，连接会一直按旧 token 过滤实时更新，直到下一次下载。
- 修改 `shards` 后，每台在线设备都会下载一次。调小时，连在被移除分片上的设备收不到实时更新，最长到 token 过期后一分钟。
- 部署改变规则后，在线设备最迟 1 小时内收到通知。
- 共享空间重建后约 60 秒内，新设备可能从缓存拿到旧数据，随后云端会让它们重新下载。
- 一次请求中依次等待约 78 次发布，就会达到 Cloudflare 的子请求上限。超出上限的分片约 1 秒后收到变更。
- 新规则把行放进超过 256 字节的 bucket 时，这些行留在空间里，但没有设备能订阅这个 bucket。

### 云端

- 级联删除读取的行数约为普通删除的两倍。
- 给已有的表加外键后，在索引建好之前，级联删除会扫描整张子表。
- `writeQuota` 下，大于 `burst` 的一批写入要等额度恢复到 `burst` 后才执行。
- `dailyWrites` 下，只要还没到上限，一批写入就会执行，即使执行后超出上限。
- 暂停中的定时任务，部署修复后仍要等满一天。对 `scheduled` 回调，先 `unschedule` 再 `schedule` 就会按计划运行。
- 新创建的空间，最初约一分钟内没有可恢复的历史。
