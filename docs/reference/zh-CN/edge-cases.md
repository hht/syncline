# 边界情况

[English](../edge-cases.md) | 简体中文

很少遇到的情况。每一种都需要不寻常的发布顺序、一次误用、一次平台故障或极端的数据量，所以大多数应用碰不到。更多情况列在[限制](limits.md#边界情况)的“边界情况”一节。

## 设备

### 剩余 4 分钟以内的 token 不会提前续期

设备会在 token 过期前 1 到 4 分钟之间重新连接以获取新 token，但前提是设备连接时这个 token 的剩余时间超过 4 分钟。

剩余 4 分钟以内的 token 会一直用到过期。之后云端以关闭码 4001 关闭连接，`downloadError` 中会显示它，设备再用新 token 重新连接。共享空间在过期后一分钟内关闭连接；私有空间在它下一次有变更或上传时关闭连接。

不会丢失任何数据。如果不想让这个关闭码出现在 `downloadError` 中，让 `token` 返回剩余时间超过 4 分钟的 token。

### 丢弃待上传的写入可能清空同步表

`resync({ discardPending: true })` 会立即撤销待上传的写入，其余的行在下载落地之前保持可见。

如果某条待上传的写入无法撤销，Syncline 会改为清空同步表，并把原因报告给应用的错误处理器。随后的下载会重新填满它们。同步表在 Syncline 之外被修改过，或者你的触发器抛错时，写入无法撤销：见[需要知道的事](limits.md#需要知道的事)中的应用触发器。

### 只有大小写不同的名字是同一个名字

表名不区分大小写，与 SQLite 一致。这一点在设备和云端的 `schema`、`localOnly`、共享空间的 schema 和 `retired` 之间都成立：

- 名字只有大小写不同的两张表不能同时声明。
- 与某个已退役名字只有大小写不同的名字就是那个已退役的名字，所以不能声明。
- 表必须按它存储时的大小写来声明。否则在设备上打开失败，共享空间在它的 `downloadError` 中显示这个失败，云端的对象则抛错。
- `retired` 中的名字不论大小写都能匹配已存储的表或列。

请一直沿用表最初创建时的拼写。

## 共享空间

### 切换用户会清空共享空间，即使它随后打开失败

用与上次不同的 `userID` 调用 `openShared`，会在这次调用之后发出的任何查询运行之前，清除上一个用户看过的行。即使空间随后打开失败（比如某次发布修改了列类型）也会清除，所以这些行不会继续可读。

只有声明本身被拒绝时这些行才会保留，比如表名已被另一个空间使用，或用了已退役的名字。

## 云端

### 类型不常见的只在云端的列在已有的表上会失败

声明为 `text()`、`integer()`、`real()` 或 `blob()`（任何 mode）的只在云端的列，可以随时添加。

其他声明，比如 `text({ length: 40 })` 或 `numeric()`，只有在表创建时就带着它们才可用。把这样的列加到已有的表上，对象启动时会抛错。已同步的 `text({ length })` 列离开 schema 后保留为只在云端的列，也会抛错。

新创建的空间会接受同样的声明，所以它可能在本地开发时通过、部署后失败。请用上面四种类型之一声明这一列。
