# 边界情况

[English](../edge-cases.md) | 简体中文

很少遇到的情况。每一种都需要不寻常的发布顺序、一次误用、一次平台故障或极端的数据量，所以大多数应用碰不到。每个应用都会遇到的规则见[限制](limits.md)。

## 表结构和值

### 仅本地表可能重复使用已删除行的主键

仅本地表上的 `autoIncrement` 不能防止主键被重复使用：主键最大的那一行被删除后，下一次插入会再次得到这个主键。

### 不能使用每个 JavaScript 对象都有的名字

表或列的名字和每个 JavaScript 对象都有的属性同名时（例如 `constructor` 或 `toString`），应用打开数据库时会抛错。云端的 `SynclineSpace` 和 `SynclineSharedSpace` 会抛错。

### BigInt 值抛出的是引擎自己的错误

BigInt 值会被拒绝。查询或写入传入 BigInt 时，抛出的是引擎自己的错误，而不是 `ValidationError`。

### SQLite 存不下的整数可能让服务端写入抛出引擎自己的错误

服务端写入超出[值](limits.md#值)一节所说范围的整数时抛出 `ValidationError`。但在 STRICT 表中，大到 SQLite 无法存成整数的值会先失败，改为抛出引擎自己的错误。除非某一列的类型 STRICT 表不接受（比如只在云端的 `numeric()` 列），Syncline 建的表都是 STRICT 表。

### 负零存成零

`-0` 会存成 `0`。

## 表进出同步

### 表离开私有空间但没有退役时保留原有的行

表离开私有空间但没有退役时，保留原有的行，直到它重新同步或登录用户切换。

### 只有空间上次打开时声明过的表，退役才会删除

只有当某个空间上次打开时声明过这张表，退役才会删除它。待上传的写入不会阻止删除。

### 共享空间不再声明的表会被清空

共享空间不再声明的表，在该空间打开时被清空。从共享空间转为仅本地的表也一样。

### 有些不再声明的表保持不动

从 `localOnly` 移除、且从未同步过的表保持不动。应用不再打开的共享空间的表也一样。

### 表重新加入同步或换空间时会被清空并重新下载

表重新加入同步、换到另一个空间，或空间首次声明它时表里已有数据，都会在任何读取之前被清空并重新下载。待上传的写入保留。

### 把同步表改名成另一张已声明的表不会被发现

把一张同步表改名成另一张已声明的表名，不会被发现。空间会把它的行当成另一张表的行。

### 表在同步表和仅本地表之间转换时保留主键行为

表保留创建时的主键行为。以仅本地表创建的表，转为同步表后仍会补上缺失的整数主键，而且每台设备补的都一样，所以每次插入都要给出主键。以同步表创建的表，转为仅本地表后仍会拒绝缺主键的插入。

## 设备

### 快过期的 token 不会提前续期

设备会在 token 过期前 1 到 4 分钟之间重新连接以获取新 token，但前提是设备连接时这个 token 的剩余时间超过 4 分钟。

剩余时间更短的 token 会一直用到过期。之后云端以关闭码 4001 关闭连接，`downloadError` 中会显示它，设备再用新 token 重新连接。共享空间在过期后一分钟内关闭连接；私有空间在它下一次有改动或上传时关闭连接。

不会丢失任何数据。如果不想让这个关闭码出现在 `downloadError` 中，让 `token` 返回剩余时间超过 4 分钟的 token。

### 丢弃待上传的写入可能清空同步表

`resync({ discardPending: true })` 会立即撤销待上传的写入，其余的行在下载落地之前保持可见。

如果某条待上传的写入无法撤销，Syncline 会改为清空同步表，并把原因报告给应用的错误处理器。随后的下载会重新填满它们。同步表在 Syncline 之外被修改过，或者[你的触发器抛错](#抛错的触发器可能阻塞下载)时，写入无法撤销。

### 抛错的触发器可能阻塞下载

同步表上的触发器在 Syncline 修改行时抛错，可能阻塞下载，或让数据库无法打开。删除这个触发器，或者让它在 Syncline 修改行时不抛错。

### 只有大小写不同的名字是同一个名字

表名不区分大小写，与 SQLite 一致。这一点在设备和云端的 `schema`、`localOnly`、共享空间的 schema 和 `retired` 之间都成立：

- 名字只有大小写不同的两张表不能同时声明。
- 与某个已退役名字只有大小写不同的名字就是那个已退役的名字，所以不能声明。
- 表必须按它存储时的大小写来声明。否则在设备上打开失败，共享空间在它的 `downloadError` 中显示这个失败，云端的对象则抛错。
- `retired` 中的名字不论大小写都能匹配已存储的表或列。

请一直沿用表最初创建时的拼写。

### 切换用户之前删除的行可能留在空闲空间里

切换用户时，被清空的行会在磁盘上清零。更早删除的行可能留在文件的空闲空间里，直到被覆盖。

### 一直写入却从不同步的应用最终会无法下载

应用在约 48,000 次启动中都有写入却从未同步，就再也无法下载。

### 下载过程中更新应用可能让下载重新开始

应用更新如果改了正在下载的表的列或索引，下载会重新开始。

### 本地列存不下的值会被放到一边

本地列类型存不下的值会被放到一边，并给出警告。带这种值到达的行，查询时看不到。

### 新增列之后把两端都回滚会停止同步

设备同步过一个新增了列的版本后，再把云端和应用都回滚，这些设备会不断重试但无法同步。云端重新声明这一列，或应用把它写进 `retired` 后恢复。待上传的写入保留。

### 较大的上传期间连接悄悄断开，要过一阵才会发现

ping 因较大的上传而暂停期间，连接悄悄断开不会被发现，直到暂停结束：一次 8 MiB 的写入最长约 2.3 小时。

### 传不完的写入会挡住它后面的写入

一次写入整体上传：上传途中断线，下次连接从头再传。如果链路总在一次写入传完之前断开，这次写入和它后面的写入都传不上去。大内容放到对象存储（例如 R2），同步指向它的引用。

### 读不回来的待上传写入会让设备停下

Syncline 自己的表（`_syncline_*`）只能由 Syncline 修改。其中保存的待上传写入读不回来时，设备无法同步，也无法打开数据库。用 `delete()` 删除本地数据库即可恢复，但待上传的写入会丢失。

### 读取待上传数量失败时保持上一次的值

读取待上传写入数失败时，`status().pending` 保持上一次的值，直到读取成功；此时正在等待的 `sync()` 和自己读取失败的 `sync()` 都会以这个错误被拒绝。写入仍会上传。

## 共享空间

### 切换用户会清空共享空间，即使它随后打开失败

用与上次不同的 `userID` 调用 `openShared`，会在这次调用之后发出的任何查询运行之前，清除上一个用户看过的行。即使空间随后打开失败（比如某次发布修改了列类型）也会清除，所以这些行不会继续可读。

只有声明本身被拒绝时这些行才会保留，比如表名已被另一个空间使用，或用了已退役的名字。

### 从订阅去掉桶会重新下载全部内容

给订阅增加桶时，只下载新增的桶。从订阅去掉桶会重新下载全部内容，新数据到达之前旧的行仍然可见。

### 不重新连接时，实时更新沿用旧 token

不调用 `reconnect()` 时，连接会一直按旧 token 过滤实时更新，直到下一次下载。

### 修改分片数会让每台设备下载一次

修改 `shards` 后，每台已连接的设备都会下载一次。调小时，连在被移除分片上的设备收不到实时更新，最长到 token 过期后一分钟。

### 在线设备得知规则改变会有延迟

部署改变规则后，在线设备最迟 1 小时内收到通知。

### 被重启打断的服务端写入可能晚到

服务端写入如果被共享空间重启打断（写入会抛错），已连接的设备可能要等到空间下一次处理请求时才收到这次改动，最迟到每小时一次的唤醒，最长 1 小时。重试这次写入会立刻送达。

### 重建之后，设备可能先从缓存拿到旧数据

共享空间重建后，设备可能先从缓存拿到旧数据，随后云端会让它们重新下载。

### 超出子请求上限的分片晚收到改动

一次请求最多能等待约 625 次推送（publish），之后就会达到 Cloudflare 的子请求上限。超出上限的分片约 1 秒后收到改动。

### 超大的桶没有设备能订阅

新规则把行放进超过 256 字节的桶时，这些行留在空间里，但没有设备能订阅这个桶。

### 正在连接的设备极少数情况下会停在最新改动之前

正在连接的设备可能会停在最新改动之前，直到下一次改动送达，或者它的 token 过期、重新连接为止。这需要依次发生：云端已放弃的一次实时更新（因为超时，或共享空间重启）在分片重启之后才到达该分片，然后设备连接时，分片查询最新改动失败。

## 云端

### 类型不常见的只在云端的列在已有的表上会失败

声明为 `text()`、`integer()`、`real()` 或 `blob()`（任何 mode）的只在云端的列，可以随时添加。

其他声明，比如 `text({ length: 40 })` 或 `numeric()`，只有在表创建时就带着它们才可用。把这样的列加到已有的表上，对象启动时会抛错。已同步的 `text({ length })` 列离开 schema 后保留为只在云端的列，也会抛错。

新创建的空间会接受同样的声明，所以它可能在本地开发时通过、部署后失败。请用上面四种类型之一声明这一列。

### 级联删除读取的行数约为两倍

级联删除读取的行数约为普通删除的两倍。

### 新加的外键会拖慢级联删除，直到索引建好

给已有的表加外键后，在索引建好之前，级联删除会扫描整张子表。

### 额度会放过一些超出上限的批次

`writeQuota` 下，大于 `burst` 的一批写入要等额度恢复到 `burst` 后才执行。`dailyWrites` 下，只要还没到上限，一批写入就会执行，即使执行后超出上限。

### 反复导致对象重置的任务会暂停一天

反复导致对象重置的任务，连续 3 次后会暂停一天，并上报失败。暂停中的任务，部署修复后仍要等满一天。对 `scheduled` 回调，先 `unschedule` 再 `schedule` 就会按计划运行。

### 给非常大的表建索引可能超过 CPU 时间限制

给非常大的表建索引可能超过 CPU 时间限制。遇到时，在 wrangler 中调高 `limits.cpu_ms`。

### 新创建的空间起初没有可恢复的历史

新创建的空间，最初约一分钟内没有可恢复的历史。
