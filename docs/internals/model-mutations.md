# Mutation testing

Details for [Models and model checking](model.md): intentionally injecting any of the following mutations causes the configuration in parentheses to report a violation, demonstrating that these configurations catch such bugs. The final section lists mutations that do not trigger violations and explains why the models' correctness does not depend on them, noting where the implementation's does.

## Private spaces (`Private.tla`)

- Omit duplicate write skipping (`MCPrivateValue`: P1)
- Apply without reverting pending writes (`MCPrivateValue`: P5)
- Revert pending writes starting from the earliest instead of reverse order (`MCPrivateValue`: P5)
- Do not delete confirmed pending writes (`MCPrivateValue`: P7)
- Do not check notice base (`MCPrivateValue`: P5)
- Omit the first version after the cookie in incremental pulls (`MCPrivateValue`: P5)
- Do not advance lmid on rejected mutations (`MCLivePrivateReject`: P9)
- Do not jump mutation IDs: treat IDs greater than `lmid + 1` as gaps (`MCPrivateJumpBackup`: P3)
- Renumber pending write IDs and do not jump IDs upon landing a full pull (`MCPrivateJumpBackup`: P11)
- Overwrite jump: set lmid to before the earliest pending write, allowing backwards pulls (`MCPrivate`: P1)
- Process pushes from old connections normally after point-in-time recovery (`MCPrivateJumpBackup`: P8r)
- Discard pending writes upon landing a full pull (`MCPrivateRestoreChunk`: P8k)
- Do not check cursor `seen` when continuing pulls (`MCPrivateIncrChunk`: P5; unreachable in single-chunk configurations where the first chunk and position are computed in the same step, making `seen` equal to watermark)
- Reuse old client ID after device restores from backup (`MCLivePrivateBackup`: P3)
- Ignore nonces when validating cookies (`MCPrivateRestore`: P8a)
- Omit log floor check when validating whether a cookie is on history (`MCPrivateTruncChunk`: P8a)
- Compare only version without nonces at the log floor (`MCPrivateTruncBackup`: P8a)
- Truncate client table along with commit log, computing lmid only from untruncated commits (`MCPrivateTruncChunk`: P1)
- Omit catch-up notice upon connection (`MCLivePrivate`: P9)
- Return only tail without scan in catch-up upon connection (`MCPrivatePromote`: P5)
- Do not disconnect when a notice on the current connection fails to chain onto the local cookie (`MCLivePrivateReject`: P9)
- Device does not verify whether a notice originates from the current connection (`MCLivePrivateRestore`: P9; the model network does not guarantee ordering, so notices from an old connection closed by recovery can arrive after closure, and matching base to the post-recovery cookie brings the device onto rolled-back history; the implementation delivers in order over a single connection and drops notices once closed)
- Allow connecting while a pull is in flight (`MCLivePrivateRestore`: P9; pull results computed before recovery arrive after a new connection is established, setting the cookie onto rolled-back history without further pulls; the implementation connects only after pulls complete and drops pull results from previous connections)
- Lost messages on a connection not treated as disconnects (`MCLivePrivate`: P9)
- Backend writes do not record touched keys (`MCPrivateBackend`: P5)
- Backend writes do not record commits and modify cloud tables directly (`MCPrivateBackend`: HistConsistent)
- Backend writes do not emit notices (`MCLivePrivateBackend`: P9)
- Do not apply deletions when applying incremental patches (`MCPrivateDelete`: P5)
- Local deletes do not record revert information (`MCPrivateDelete`: P5)
- Discard pending writes on user-requested resync (`MCLivePrivateRefetch`: P5)
- Do not clear the refetch flag after landing a full resync (`MCLivePrivateRefetch`: P9; connection never establishes, pending writes never push)
- Hold and advance sequence numbers even for storage errors (`MCPrivateStorage`: P2)
- Skip mutations with storage errors and process subsequent mutations normally (`MCPrivateStorage`: P3)
- Backend write row deletes do not record keys (`MCPrivateDeleteBackend`: P5)
- Execute writes modifying tables that left sync normally (`MCLivePrivateRetire`: P10; P2 shares the same `Exec` predicate to judge execution, so both mutate together and cannot report)
- Reject entire batch without advancing sequence numbers when a write modifies a table that left sync (`MCLivePrivateRetire`: P9)
- Omit hints to other online devices when storage errors occur after earlier writes in the batch committed (`MCLivePrivateStorage`: P9)
- Do not record target version when dropping unchainable notices (`MCLivePrivateHintGap`: P9)
- Do not write `since` when entering sync (including re-entering after leaving) (`MCPrivatePromote`: P5)
- Point-in-time recovery to before entering sync does not re-record `since` on restart (`MCPrivateRestorePromote`: P5)
- Tail does not skip items at or before `since` in the scan set (`MCPrivateScopeTwice`: P5)
- Deletions in tail are exempt from skip rules (`MCPrivateScopeTwice`: P5)
- Do not open the next round upon catching up to head (`MCPrivateScopeEnter`: P5)
- Devices do not delete rows upon receiving `drop` ops (`MCLivePrivateRetire`: P10)
- Do not record drops according to the current scope after point-in-time recovery (`MCPrivateScopeRestore`: P10)
- Deliver zero confirmed mutation IDs (`MCLivePrivate`: P7)
- Requested range pull ranges not included in the scan set (`MCLivePrivateRange`: P5; corrupted rows are treated as recovered without receiving cloud values)

## Shared spaces (`Shared.tla`)

- Do not trigger full resync when buckets are removed from subscription (`MCShared`: S1)
- Tail emits only rows in subscription after modification, ignoring state before modification (`MCShared`: S1)
- Do not discard staged chunks when response subscription differs from staged chunks (`MCShared`: S1)
- Notices do not compare subscriptions (`MCShared`: S1)
- Do not clear tables at the start of a full pull (`MCSharedRebuild`: S1)
- Do not clear table before scanning it in each round (`MCSharedRule`: S1)
- Apply final chunk without checking `seen` (`MCSharedChunk`: S1)
- Do not open the next round upon catching up to head (`MCSharedRule`: S1)
- Subsequent pull requests computed before current round watermark (i.e. cache keys exclude watermark) (`MCSharedRule`: S1)
- Notices compare only version without incarnation (`MCSharedRebuild`: S1)
- Notices do not check base (`MCSharedRebuild`: S1)
- Apply notices while staged chunks exist (`MCSharedRebuild`: S1)
- Apply notices while pulls are in flight, and omit comparing pull results against cursor (`MCSharedRebuild`: S1)
- Devices ignore hints (`MCLiveShared`: S2)
- Drop unchainable newer notices directly without advancing target version (`MCLiveShared`: S2)
- Send only empty catch-up on connect without hints when device is lagging (`MCLiveShared`: S2)
- Do not pull when subscription heard on connection differs from landed subscription (`MCLiveShared`: S2)
- Drop target when landed incarnation differs from target incarnation, without checking whether the request included it as a floor (`MCLiveSharedRebuild`: S2)
- Shard connects late-arriving rounds from an older incarnation by version and pushes cross-incarnation notices (`MCSharedLate`: S1)
- Return incremental instead of full pulls when cookie is earlier than log floor after truncation (`MCSharedTrunc`: S1)
- Continue reading when mid-pull plan versions are earlier than log floor after truncation (`MCSharedTrunc`: S1)
- Shards push notices even when a version truncated since the previous pushed version touched the subscription (`MCSharedTrunc`: S1)
- Do not drop target when landed incarnation differs from target incarnation (`MCLiveSharedLate`: S2; device continues pulling with a target from another incarnation)
- Shard pushes hint for late-arriving older incarnation round without pushing queried head version (`MCLiveSharedLate`: S2; after device lands on old incarnation, shard assumes head was pushed and stops pushing, stalling device on old incarnation)
- When notices received before catch-up differ in incarnation from queried head, stop querying and do not push head version (`MCLiveSharedLate`: S2)
- Connections using expired tokens are not closed on expiration (`Expire` is unfair: shards do not close on expiry and integrators do not call `reconnect()`; `MCLiveShared`: S2; connection continues pushing with original subscription)
- When landed pull subscription differs from heard subscription on connection, invalidate heard subscription without switching connections (`MCLiveShared.big`: S2; subscription reverts to original, connection ceases messages, and device stalls on intermediate subscription)

## Fanout (`Fanout.tla`)

- Advance progress even when deliveries are lost (`MCFanout`: S2)
- Record queried head version during catch-up into shard known version (`MCFanout`: S2; resident devices miss the swallowed round)
- Pulls after receiving hints omit floor (`MCFanout`: `NoWastedPull`)
- Versions without keys (rule changes, rebuilds) not treated as "too many" (`MCFanout`: `Covers`)
- Send empty catch-up chained onto device cookie when head version cannot be queried (`MCFanout`: `Covers`)
- Shard acknowledgments adopt head instead of reverting to persisted version after shared space actor restart (`MCFanout`: S2)
- Tokens never expire (`Expire` removed; `MCFanoutLate`: `CatchesUp`; a round the fanout gave up on reaches the shard after a reset, moves its known version back, and the hint it pushes to a device whose catch-up was lost names a version the device then holds, so nothing tells it about the latest)

## Schedule (`Schedule.tla`)

- Run every due entry together even when one of them never finished a run (`MCSchedule`: `Bounded`; with `Bounded` removed, `Served`: tasks cut off alongside a crasher never finish)
- Never pause an entry that reached `ResetLimit` (`MCSchedule`: `Bounded`)
- Keep the lease and reset count of a delivery across a restart instead of replacing its entry (`MCSchedule`: `Exempt`)

## Ownership (`Ownership.tla`)

- Keep tables no space records on a private owner switch (`MCOwnership`: `NoLeak`)
- Keep the rows of a table turning local-only from a shared space (`MCOwnership`: `NoLeak`)
- Keep the rows of a table a shared space no longer declares (`MCOwnership`: `NoLeak`: no owner switch reaches it any more)
- Keep the rows of a table never synced that a space declares for the first time (`MCOwnership`: `Exact`: local-only writes would never upload)
- Leave another space's record of a table a space declares (`MCOwnership`: `Exact`: the old space takes it back without refetching)
- Wipe only the declared tables on a shared space owner switch, not the ones it recorded last time (`MCOwnership`: `NoLeak`)
- Drop every retired table that was ever synced, not only the ones a space records (`MCOwnership`: `LocalKept`)
- Keep the cookie of a space whose table the app dropped and declaring recreated, as the space still records it (`MCOwnership`: `Exact`)

## Mutations that do not trigger a violation

Correctness of the models does not depend on them; an item says so where the implementation's does:
- Applying notices chained onto the cookie while staged chunks exist: full exhaustive check on `MCPrivateRestoreChunk` and random walk on `MCPrivateIncrChunk` still pass. Chunks contain values current at read time and positions must be on current history; advancing the cookie via notices before continuing pulls still yields correct landed state. The implementation freezes notices during pulls for simplicity.
- Range pulls do not require zero pending writes: full exhaustive check on `MCPrivateRange` still passes. Range pulls return head values, and landing reverts, applies, and replays pending writes as usual. "Zero pending writes" is a precondition for checksum comparison (local tables do not equal any cloud version when pending writes exist), but writes can still occur after a range pull is issued in the model.
- Shared space tails do not skip items at or before `since` in the scan set: `MCSharedRule` still passes. `Shared.tla` has no table leaving sync, so its log holds no table drop entries, and tails emit current values: extra items only cause redundant reads in the model. The implementation does depend on the skip: a shared table leaving sync records a drop, and without the skip a pull spanning the table's return drops the rows it has just rescanned (`test/cloud/shared-evolution.test.ts`); private space skips guard table deletions (`MCPrivateScopeTwice`).
- In shared spaces, first request after a hint omits the target floor (waiting until the request after landing to include it), and requests whose floor is not in the cloud's current incarnation still use cache: `MCLiveSharedRebuild` passes in both cases. Both optimizations only reduce stale cache reads and redundant pulls. Dropping targets from another incarnation depends only on "this request included it and the response was not from that incarnation", regardless of when it was attached.
